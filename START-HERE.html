燕小北桌宠：第一次安装，从这里开始

选下载包怎样解压Windows 安装原生素材安装Mac 安装日常使用更新与卸载更多说明

个人制作，非官方产品。本文不要求你会编程。解压后双击根目录的 START-HERE.html，就能用浏览器阅读同一份说明，不用安装 Markdown 阅读器。版本号在根目录 VERSION.txt。

第一步：只选一个适合你的包

  • Windows 电脑，想看额度和任务：下载 bjut-yanxiaobei-windows.zip。大多数 Windows 用户选它。
  • 只想给 Codex 自带桌宠换成燕小北，不要额外额度面板：下载 bjut-yanxiaobei-native.zip。Windows / 兼容的 Mac 宿主使用同一份素材。
  • Mac 电脑，想看额度和任务：下载 bjut-yanxiaobei-macos.zip。注意：目前是实验性源码包，首次仍需按下面步骤构建，尚无经过 Mac 实机验收的签名安装包。
  • 想改代码或上传 GitHub：才下载 bjut-yanxiaobei-codex-pet.zip。普通使用者不必下载全部四个包。

这些包互不依赖。不要把旧的 CodexQuotaPet.zip、YanXiaoBeiPrivatePet.zip 当成最新版，也不要混合不同版本中的文件。

在 GitHub 下载时，进入本项目仓库的 Releases（发布）页，打开作者发布的版本，再从 Assets（附件）找上述文件名。不要把绿色 Code 按钮里的 Download ZIP 当成专用安装包。仓库/Release 尚未发布时不会有附件，请使用作者实际发给你的包；本文没有虚构下载地址。

第二步：解压，不要直接在压缩包里运行

  • Windows：在“下载”文件夹找到 ZIP → 右键 → 全部解压 / 提取全部 → 选择你长期保留的位置 → 提取。进入新出现的普通文件夹；地址栏里不应仍有 .zip。
  • Mac：在“访达”的“下载”里双击 ZIP，进入解压出的文件夹。建议移到“文稿”等长期保留的位置。
  • 不要只拖出 Start.vbs、Start.command 或一张图片。必须保留整个文件夹和子文件夹。

打开后应能看到 START-HERE.html、VERSION.txt、README.md，以及与你选择的版本对应的 windows-companion、macos-companion 或 codex-native 文件夹。若多套一层同名外壳，继续进入直到看到这些文件。

下面按你选择的版本阅读即可，其他部分可以跳过。

A. Windows 增强版：日常只需要双击

A1. 先确认 Codex 能用

打开你电脑上的 Codex，登录自己的账号，确认能正常发消息、完成任务。没有安装 Codex 时先通过其官方渠道安装；燕小北不附带 Codex，也不提供账号。不要把密码、API Key 或 auth.json 发给桌宠作者。

A2. 安装一次 Node.js（已有合适版本可跳过）

Node.js 是桌宠连接数据时需要的运行环境，不是另一个账号，也不需要付费注册。

1. 打开 Node.js 官方下载页。选择 LTS（长期支持）版本，推荐 24 LTS；本项目 Windows 最低要求 22。

2. 系统选择 Windows，下载 Installer / 安装程序（.msi），不要选源码、Docker 或独立二进制 ZIP。

3. 大多数 Intel / AMD 电脑选 x64。若不确定，打开 Windows 设置 → 系统 → 关于，看“系统类型”；明确写 ARM 的机器选对应 ARM64 安装包。Windows ARM64 上本项目尚未实测。

4. 双击下载的 .msi，阅读安装提示，使用默认设置安装；保留 Add to PATH 选项。若出现额外的原生模块构建工具选项，本项目不需要勾选。不要因为桌宠去关闭杀毒软件。

5. 安装完成后关闭安装器。如果首次启动仍说找不到 Node，重新登录 Windows 后再试。

想确认是否装好：按 Win + R，输入 cmd，回车；在打开的窗口输入下面这一行并回车：


node --version

出现 v22.x.x、v24.x.x 或更高的版本号表示能找到 Node。若提示“不是内部或外部命令”，重新检查安装与 PATH，不用修改任何桌宠代码。检查后这个 CMD 窗口可以关掉。

A3. 启动桌宠

1. 若已经有旧燕小北，先右键关闭旧桌宠；如果旧版开了跟随启动，也先在旧版关闭它。第一次使用的人跳过此步。

2. 打开解压目录中的 windows-companion 文件夹。

3. 双击 Start.vbs，只点一次，给首次连接一点时间。

4. 燕小北出现、额度气泡开始显示数字，就是启动成功。没有任务时显示空闲是正常的。

若 Windows 隐藏扩展名，你可能只看到 Start：先在资源管理器“查看 / 显示”中勾选“文件扩展名”，确认是 Start.vbs。不要双击 .ps1、.js、.xaml 文件，也不要把它们拖进 Codex。

正常 Start.vbs 不会留下 CMD / PowerShell 窗口。程序不是单文件 EXE；双击现有入口和一个正式安装器不是一回事。

A4. 下次怎样打开？

以后直接回到这个文件夹，双击 Start.vbs，不用重装 Node。也可以右键 Start.vbs → 显示更多选项（如果有）→ 发送到 → 桌面快捷方式。这里只创建快捷方式，不要把 Start.vbs 单独移动到桌面。

想只留一只燕小北：在 Codex 里隐藏原生桌宠，保留独立增强版即可；不需要卸载 Codex。

A5. 没反应或连接失败怎么办？

  • 完全没出现：检查是否在 ZIP 中运行、Node 是否装好、旧桌宠是否还在。单实例保护会阻止再开第二只。
  • 双击 Start.vbs 打开了编辑器：不要更改脚本内容。尝试“打开方式”中的 Microsoft Windows Based Script Host；没有该选项或公司电脑禁止脚本时，不要解除安全限制，联系管理员或使用详细安装指南中的手动入口。
  • 仍然打不开：双击同目录 Start-Debug.cmd，它会故意保留错误窗口。把错误文字脱敏后反馈，不要上传账号文件。调试结束按窗口提示退出，日常仍用 Start.vbs。
  • 燕小北出现但额度一直未知：先确认 Codex 登录和订阅，再右键刷新。不同客户端安装位置可能需要配置 CLI 路径，见详细指南；不是所有账号模式都提供订阅额度。
  • Windows 弹出安全拦截：先核对来源和文件，不要选择关闭全局保护来“解决”。

B. 原生素材版：复制文件夹，不安装运行环境

此版本只改变 Codex 自带桌宠的外观，不额外添加五小时、每周额度气泡。不需要 Node.js、npm 或 PowerShell。

B1. Windows 手动安装

1. 在解压目录打开 codex-native，找到名为 bjut-yanxiaobei 的文件夹。里面应有 pet.json 和 spritesheet.webp 两个文件。

2. 复制整个 bjut-yanxiaobei 文件夹，不是只复制其中一张图片。

3. 按 Win + R，粘贴下面的路径，回车：


%USERPROFILE%\.codex

4. 在打开的位置寻找 pets 文件夹；没有就新建文件夹并命名为 pets，再打开它。

5. 把刚复制的 bjut-yanxiaobei 粘贴进 pets。如果已有同名目录，先取消替换并备份旧目录，不要直接覆盖。

6. 回到 Codex，在支持此功能的版本中打开设置 → Pets / 桌宠 → Refresh / 刷新，选择 BJUT 燕小北，然后显示桌宠。菜单可能随客户端版本不同而变化。

如果第 3 步提示目录不存在，先确认你确实已运行并登录 Codex。只有明确设置过 CODEX_HOME 的用户才改用该自定义目录，不要随意猜路径。

B2. Mac 手动安装

1. 找到解压目录下 codex-native 中的 bjut-yanxiaobei 文件夹，复制整个文件夹。

2. 在“访达”按 Command + Shift + G，输入下面的路径并回车：


~/.codex

3. 打开或创建 pets 文件夹，将 bjut-yanxiaobei 粘贴进去。同名旧目录先备份。

4. 回到支持 v2 自定义桌宠的 Codex 宿主，刷新宠物列表并选择 BJUT 燕小北。

Mac 原生宿主未在本次发布中实测。如果客户端没有 Pets / 桌宠功能，仅复制文件不会给它增加这个功能。不要尝试修改客户端程序。

最终应是 pets → bjut-yanxiaobei → pet.json 和 spritesheet.webp，不能多套一层 bjut-yanxiaobei。素材里的 spriteVersionNumber: 2 是图片格式编号，不是软件仍停在“第 2 版”。

C. Mac 增强版：首次按步骤准备，以后双击 .app

先说明：目前这一路还不是真正的一键安装。没有 Mac 实机验收和签名/公证，不保证每台 Mac 都能直接运行。完全不想接触终端的人，建议先选原生素材版（同样需兼容宿主），或等作者提供经过验证的 Mac 安装包。

C1. 确认系统与芯片

点击屏幕左上角苹果菜单 → 关于本机：系统需 macOS 13 或更新。芯片写 Apple M 系列的是 Apple Silicon；写 Intel 的是 Intel Mac。只记住你属于哪一种，后面选一条对应命令即可。

C2. 安装 Node.js，一次即可

打开 Node.js 官方下载页，选择 LTS，推荐 24 LTS；Mac 构建最低要求 22.12。系统选 macOS，下载 Installer（.pkg）并按安装向导安装。不要选源码包、Docker 或不明第三方安装脚本。

先正常安装并登录 Codex，确保它能工作。下载并完整解压 bjut-yanxiaobei-macos.zip。

C3. 打开终端并进入正确文件夹

1. 按 Command + 空格，输入“终端”或 Terminal，回车。终端是系统自带工具。

2. 在终端输入 cd，再按一次空格，暂时不要回车。

3. 从访达把解压目录中的 macos-companion 文件夹拖到终端窗口里。系统会自动填路径，不用你输入用户名。

4. 按回车。接下来所有命令都在这个终端继续执行。

只复制下面代码框中的命令，不要复制代码框标题。每次粘贴一行、按回车、等它结束并重新出现可以输入的提示符，再执行下一行。


node --version

应出现不低于 v22.12.0 的版本号。若 command not found，先完成 Node 安装并重新打开终端，不要继续后面的步骤。


npm ci

这一步会联网下载依赖，可能需要几分钟。出现 warn 不一定代表失败；出现 npm error、下载错误或命令失败时先停下，保留脱敏错误文字，不要继续打包。


npm run prepare-assets

应提示 Prepared/validated ... resources。


npm test

应看到测试通过，fail 为 0。测试失败时先排错，不要继续。

C4. 生成应用，只选一条

如果是 Apple M 系列，复制这一条：


npm run pack:arm64

如果是 Intel，复制这一条：


npm run pack:x64

不要两条都执行。等待命令成功结束，再在访达打开 macos-companion → dist，继续进入对应的子文件夹，找到 BJUT YanXiaoBei.app。Finder 隐藏扩展名时可能只显示 BJUT YanXiaoBei，类型应为应用程序。

C5. 放好应用，以后双击即可

1. 复制整个 BJUT YanXiaoBei.app，不要右键“显示包内容”后只复制里面的文件。

2. 在访达按 Command + Shift + H 回到个人主文件夹，打开 Applications / 应用程序。没有可新建名为 Applications 的文件夹。

3. 粘贴应用，双击启动。出现桌宠或菜单栏图标后，可以关闭构建用的终端。

4. 以后直接双击这里的应用，不用再次执行 npm，不依赖系统 Node。源码文件夹可先保留，便于更新和排错。

系统若阻止打开：先核验来源和构建结果。当前是未签名开发包，不要全局关闭 Gatekeeper、杀毒或复制所谓“强制解锁”命令。需要稳定的一键体验，应等待作者完成签名、公证和真机测试。

C6. 首次连接失败

右键桌宠，或点菜单栏图标 → 选择 Codex 应用…，选你真实安装的 Codex.app。仍连不上时需要可用的 Codex CLI：CLI 是 Codex 的命令行程序，不是 API Key。不会配置它的用户先停止并反馈，不要随机下载脚本或把 .app 文件夹当成 CLI。详细路径操作见 Mac 专用指南。

npm start 只是开发调试入口，会依附终端；日常不要用它代替构建好的 .app。Start.command 是装好依赖后的后台源码入口，不是自动安装器，详细说明见 Mac 专用指南。

第三步：日常怎么用？

  • 拖动角色或面板标题区：移动桌宠，限制在屏幕工作区。
  • 双击角色：打开或激活 Codex，不主动新建任务或导航到首页。
  • 点击“任务 / 进行 / 等待 / 完成”摘要行：展开或收回任务列表。
  • 点击具体任务：跳转到该任务，需本机 Codex 支持并能访问它。
  • 气泡右上角 ×：只隐藏额度气泡，不是退出桌宠。
  • 右键：分别显示/隐藏额度气泡、任务队列，刷新，清除提醒，关闭桌宠。Mac 也可用菜单栏图标找回。
  • 不想看气泡：右键隐藏它；不是删文件。
  • 不想开两只：在 Codex 内隐藏原生桌宠即可。
  • “重置 ×N”：只是可用次数，不能点击购买或兑换。-- 表示未知，不等于 0。
  • 任务列表是观察到的近期活动，不是全部历史任务。需要确认、出错、完成提醒的优先级高于思考；有疑问先展开列表。

第四步：自动启动、更新与卸载

自动启动默认关闭。先手动启动成功，再考虑开启：Windows 右键“跟随 Codex 启动”；Mac 的“跟随显示”仅在桌宠已运行时有效，还需另行配置登录项。未签名 Mac 包的登录项尚未验证，不保证勾选后生效。

更新：先退出旧桌宠、关闭旧版跟随启动，保留旧目录备份；把新 ZIP 解压到新位置，确认 VERSION.txt 是新版本，按对应入口启动，再按需开启跟随。不要把旧文件覆盖回新目录，移动目录后旧快捷方式也要重建。

如果关闭新桌宠后，重开 Codex 又出现旧版，通常是旧观察器或旧快捷方式仍在。仅更新 ZIP 或从新版菜单关闭自启动，不一定能停掉旧私人版观察器；请先按旧版说明关闭它。没有把握时反馈作者，不要结束所有 Node / PowerShell 进程。

卸载增强版：先关闭跟随/登录项，再右键退出，将自己的桌宠目录或 .app 移入回收站/废纸篓。原生版则先隐藏或换别的桌宠，再移走 pets 下面的 bjut-yanxiaobei。两者都不需要删除整个 .codex 或 Codex 的账号和任务。
