# 架构与维护

[返回首页](../README.md)

## 三种版本的职责

```text
同一个燕小北角色
├── v2 WebP 图集 + pet.json → Codex 原生桌宠宿主 → 宿主负责动画、状态与活动交互
├── PNG 动作帧 → macOS Electron 独立窗口（本地 IPC + utilityProcess）
└── PNG 动作帧 → Windows PowerShell / WPF 独立窗口
                    ↑ 本地状态 JSON + stdin 命令
               Node.js 数据桥
                    ├── Codex app-server：额度、重置次数、任务元数据
                    ├── 本机 session_index.jsonl：任务标题补充
                    ├── Codex 桌面日志：发现任务、审批及活动补充
                    └── 本机会话 JSONL：开始、完成、中止的逐轮校验
```

## 文件职责

下表是 Windows 目录中的规范源。Mac 的 `main.cjs` 负责透明窗口、菜单栏、拖动、应用激活与桥接进程；`preload.cjs` 仅暴露白名单 IPC；`ui/renderer.js` 负责文字、折叠列表与动画；`lib/model.cjs` 提供独立可测的布局、边界、任务链接和离线判定。

`platform-paths.js` 统一平台路径。Mac 的 `scripts/prepare-assets.cjs` 同步四个共享运行模块、57 张帧、时序和许可，生成 SHA-256 清单；不能手改副本代替规范源，发布前必须同步校验。

| 文件 | 职责 |
| --- | --- |
| `MainWindow.xaml` | 透明窗口、额度气泡、任务活动面板 |
| `animation-timing.json` | 独立版播放时长及原生标准预览时长的唯一配置 |
| `CodexQuotaPet.ps1` | 动画、拖动边界、可见性、右键交互、桥接进程管理 |
| `CodexDesktop.ps1` | 区分桌面客户端和 CLI、恢复已有窗口、冷启动客户端 |
| `quota-bridge.js` | 通过 stdio JSON-RPC 连接本机 app-server，读取额度并组合活动数据 |
| `activity-state.js` | 逐轮状态记录、迟到事件防护、会话尾部增量读取 |
| `Runtime.ps1` | 数据目录与 Node 路径解析 |
| `Start.vbs` / `Launch.ps1` | 无终端启动与错误提示 |
| `CodexPetWatcher.ps1` | 观察 Codex 桌面进程生命周期，尊重手动关闭桌宠 |
| `Configure-Autostart.ps1` | 新安装首次启动设置当前用户登录项；记录人工开关选择，防止关闭后反弹 |

运行态 JSON 不存进源码目录。桥接进程随窗口关闭退出；观察器仅在启用跟随启动后运行。

## 状态与刷新频率

窗口主状态选择顺序：`waiting > failed > ready > active > idle`。对应动作：`waiting`、`failed`、`review`、`running`、`idle`。左右拖动覆盖为相应移动动作，释放后回到基础任务状态；只做垂直拖动时不强行切换左右动画。

| 数据或行为 | 默认间隔 / 规则 |
| --- | --- |
| Codex 额度 | 收到 app-server 更新通知立即应用；任务进行中最多每 20 秒查询，空闲时最多每 60 秒查询；任务结束后合并触发一次查询；支持手动刷新 |
| 任务元数据与标题 | 20 秒 |
| 桌面日志增量读取 | 1 秒；启动时有限量回读 |
| 已观察任务的会话增量读取 | 1 秒；每文件每轮最多 4 MiB，首次读取尾部；目录索引每 20 秒更新 |
| 活动心跳 / 界面离线检测 | 5 秒 / 超过 15 秒无活动快照，或数据桥退出 |
| Windows UI 状态文件检查 | 500 毫秒；仅额度内容变化时重绘额度，不把活动心跳误当作额度更新 |
| Mac UI 通信 | utilityProcess 消息；每秒检查快照新鲜度 |
| 倒计时刷新 | Windows 30 秒；Mac 1 秒（不增加额度 API 请求） |
| 启动观察器 | 2 秒 |
| 完成 / 错误提示有效期 | 10 分钟 |
| 运行 / 等待状态无更新兜底 | 12 小时 |

状态未变不会重新开始一轮动画；任务标题 / 状态未变不会重建整个列表。显示行以短标签和独立计数列避免拥挤，大于 99 的数量显示 `99+`，提示文本保留精确数量。

0.1.2 起，`task_complete` 会直接结束同轮运行状态，不要求桌面弹出通知；`turn_aborted` 移除运行/等待状态，不制造成功或失败提醒。状态按任务、轮次 ID 和开始时间校验，旧轮结束事件、重复通知与日志回读不能结束新轮或重新弹出已清除的提醒。普通思考进展不代表审批已被答复；带 ID 的多个审批须逐个解除。错误提醒与完成提醒均在 10 分钟后过期。

重启时从当前桌面日志发现任务（包括恢复任务记录），再读取这些任务的会话尾部恢复状态，不扫描并展示全部历史任务。0.2.2 起，两平台都通过 app-server 的来源字段或会话头部元数据确认主任务；最多读取 256 KiB 头部用于分类，排除内部临时会话、带父任务标记的子 agent 及 guardian/review/compact 等子会话。名称本身不构成可信来源，未知来源确认前不显示。打开旧任务及首次读取已完成历史只静默建立状态，不制造新完成提醒；真实执行中的主任务会继续显示并跟踪后续结束事件。

仅保存生命周期字段和待处理请求 ID，不把对话、推理或工具输出复制进状态文件。结构化会话项识别权限/用户输入请求及其匹配结果，桌面审批响应缺少任务 ID 时以请求 ID 关联主任务。普通 `require_escalated` 工具调用及由 `auto_review` 审查的 `request_permissions` 不等于人工等待；数据桥从桌面每轮配置读取实际审批人，自动审查期间忽略泛化审批事件，但明确展示给用户的审批界面仍进入等待。提问工具独立处理，自动审查配置不抑制真正需要回复的问题。无有效审批人日志时沿用兼容判断，不能保证辨别所有未来客户端格式。没有本地会话、事件格式不兼容或超过尾部回读范围时，已确认来源的主任务仍只能依靠日志及 12 小时兜底，不能保证远程任务与崩溃丢失事件的准确性。正常长任务不因短时间没有文本输出而被判定完成。数据桥退出或心跳过期时显示“状态离线”、未知计数并停用思考动作，不把断线当作任务完成。活动快照中的 bridgeVersion 可用于核对实际运行版本。

## 兼容性边界

Mac 还从 app-server 返回的最近 12 小时内本机根任务发现会话，跳过 sub-agent 元数据。这是没有兼容桌面日志时的生命周期降级，不保证覆盖审批/错误或远程任务，不把全部历史任务塞入队列。Mac 的“跟随显示”只在应用运行时工作，与 Windows 独立观察器不同。

Electron 使用自定义本地协议、CSP、沙盒渲染器、上下文隔离和受限 preload；不向页面开放 Node、任意 shell 或文件读写。IPC 校验调用页面，拒绝新窗口和导航；任务链接必须是当前列表中的合法 UUID。Mac 激活已有应用用系统 open -a，不主动跳首页，具体多窗口前台选择由系统决定。系统权限和登录项仍须 Mac 实机验收。[Mac 指南](MACOS.md)

原生版无需增强版的数据桥。增强版不修改 Codex 代码，也不注入其窗口；但它使用的 app-server 结构和桌面日志不是稳定的第三方桌宠接口。日志识别、CLI 安装目录和 Windows 应用标识都有版本依赖。

恢复已有窗口使用 Windows 窗口句柄，不调用“新任务”深层链接。只有用户点击具体任务行才使用经 UUID 格式校验的任务链接。项目不发送任务内容、不代替用户确认审批、不购买或兑换额度。

## 测试与预览

`scripts/Test.ps1` 分别启动隔离的 PowerShell 测试进程，验证布局、128 组文字宽度、30 个边界样例、窗口恢复决策、任务跳转、观察器和打包安装逻辑。Node 单元测试使用内存状态和模拟文件系统，不连接真实 app-server。安装 / 自启动测试使用 `.test-output/` 下的假目录。

`scripts/Render-Previews.ps1` 使用同一 XAML 和实际布局函数渲染预览，以虚构标题、额度与任务 ID 展示；不采集桌面，不打开真实窗口。

增强版的 57 张 PNG 由 `scripts/Sync-Frames.py` 从最终批准的 v2 图集逐格无损导出，避免使用早期带绿边的中间帧。该维护工具需要 Python 和 Pillow，普通用户运行桌宠不需要它们。

`scripts/Render-Animations.py` 从同一套帧与 `animation-timing.json` 生成 GIF：`docs/animations/` 对应增强版实际时序，`docs/animations/native/` 对应原生标准时序。普通用户无需 Python；只有维护和重新渲染动图时需要 Python / Pillow。

0.1.1 仅替换 `failed` 动作行；其余 10 行像素保持不变。增强版出错循环为 3.6 秒，其他动作时长未改。原生素材包不能控制官方宿主的帧率，因此原生版通过降低动作幅度改善观感，不宣称与增强版具有相同循环时长。
